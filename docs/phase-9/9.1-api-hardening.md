# Phase 9.1 — API Production Hardening

## Changes

- JSON 404 handler (`http/middleware/not-found.ts`) for all unmatched routes.
- Helmet security headers (explicit CSP `default-src 'none'` +
  `frame-ancestors 'none'` for the JSON API; embedder policy off).
- CORS allowlist (`CORS_ORIGINS`, comma-separated; legacy `CORS_ORIGIN`
  fallback; `*` rejected; disallowed origins get JSON 403).
- Explicit JSON body limit (`BODY_LIMIT`, default `100kb`, max 5mb;
  oversized bodies get JSON 413 `BODY_TOO_LARGE`).
- Request timeout middleware (default 30s; 503 `REQUEST_TIMEOUT`;
  ends the HTTP response only — domain/chain/tx state untouched, no
  AbortController into operations).
- `/health` stays liveness-only; new `/ready` checks PostgreSQL
  connectivity + applied migrations and reports the Midnight mode
  honestly (SIMULATED is declared as-is, never as a live network;
  REAL reports configured-but-unverified). 200 ready / 503 not.
  Responses contain booleans and mode names only.
- Graceful shutdown (`shutdown.ts`): SIGTERM/SIGINT drain with bounded
  grace, pool close, clean exit; repeated signals force exit; no
  `process.exit` in business logic; testable controller + installed
  process handlers.
- Uncaught errors: `uncaughtException`/`unhandledRejection` log (sliced,
  structured) and drain; the process never pretends health afterwards.
- Error sanitization: `ApiError` and `DomainError` messages pass
  through (both constructed internally from IDs/enums); `MidnightError`
  maps to fixed per-code messages; everything else (pg errors included)
  becomes generic `INTERNAL_ERROR`; internals go to structured logs only.
- Attestor verdict route now declares `requireAttestor` middleware
  (service-level secret check retained as defense in depth, plus
  identity-match guard).
- Config hardening: `NODE_ENV` validated; production requires explicit
  `CORS_ORIGINS` and forbids `DEV_AUTH_TOKEN`; numeric/log-level
  values validated; secrets never defaulted.

## Middleware ordering

helmet → CORS → `express.json(limit)` → request-id → timeout →
routes → 404 → error handler.

## Tests

`apps/api/src/production.test.ts` (17 tests): JSON 404s, headers, CORS
allow/deny + prod config validation, oversized body, timeout
fire/no-fire, `/health`, `/ready` (success, DB-down, schema-missing),
shutdown drain/force/handler wiring, error sanitization (domain,
pg-style, adapter-style), config defaults.

## Known limitations (explicitly later phases)

- Worker scheduling is Phase 9.4 (worker entry points exist, no timer).
- DB transaction atomicity + migration locks are Phase 9.2.
- Wallet authentication is later (dev sessions unchanged otherwise).
- REAL Midnight remains blocked (devnet/wallet).
- No rate limiting yet (9.5); no metrics (9.6); no Docker/CI changes.
