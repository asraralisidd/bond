# Phase 9.3 — Production Authentication & Authorization Hardening

## Authentication architecture

Three non-confusable principals (`http/principals.ts`): **operator**
(session bearer → owner resources), **attestor** (`X-Attestor-Secret` →
verdict submission only), **system** (internal worker paths, never a
bearer token, factory reserved for Phase 9.4+). Raw tokens never leave
middleware: services receive IDs, never credentials.

## Operator principal

Unchanged mechanism, hardened edges: pre-shared dev key → opaque
session (`sess_<24hex>.<64hex>`, `randomBytes`), SHA-256 hash at rest,
24h server-side expiry, revocation flag. New: `POST /auth/sign-out`
revokes the caller's session; timing-safe dev-key comparison.

## Attestor principal

Unchanged credential model (per-attestor secret, hashed, active-status
gated) with timing-safe comparison added. Isolation verified by test:
attestor secrets cannot touch operator routes (401, no bearer);
operator bearers cannot submit verdicts (401, no secret); wrong
secrets rejected. Verdict submission additionally binds attestorId in
body to the authenticated attestor (403 on mismatch).

## System principal

Type + factory only. No bearer form exists; nothing constructs it from
request input. Worker/reconciliation paths keep their existing
`system:*` actor strings until Phase 9.4 adopts the type.

## Development authentication

`DEV_AUTH_TOKEN` remains dev-only. New: per-IP failure counting on
`POST /auth/session` (20 failures / 10 min → 401), explicitly
documented as a dev-boundary speed bump, unreachable in production
(config forbids the token there). Production without a wallet provider
fails closed: session issuance refuses, so no production deployment
can accidentally run on dev auth.

## Production authentication boundary

`NODE_ENV=production` + `DEV_AUTH_TOKEN` set → startup throws.
Without it, `/auth/session` returns 401 "not enabled". Wallet
authentication is **not implemented** — no Lace APIs invented, no fake
wallet sessions. Phase 11 owns: challenge/nonce protocol, signature
verification, `operators.wallet_address` binding, session issuance
from verified signatures.

## Session lifecycle

CREATE (random token, hashed) → ACTIVE (expiry + revocation checked
per request, server time) → EXPIRED / REVOKED (both rejected; revoked
sessions never refresh). No `last_used_at` column was needed — idle
expiry is deferred, documented below. No raw token is ever persisted
(tested), logged, or returned except once at issuance.

## Token hashing

SHA-256 of the full bearer string (`sess_<id>.<secret>`), compared in
constant time where performed in JS (dev key, attestor secret).
Session lookup itself is hash-equality in SQL. No custom crypto:
`node:crypto` primitives only.

## Authorization model

Central `services/authorization.ts`: `requireAgentOwnership`,
`requireBondOwnership`, `requireTxOwnership` (agent → bond →
deny-orphan), `requireFlagOwnership`,
`requireAttestationOwnership` (via flag → agent). Applied to
transaction GET/advance/confirm (previously missing — cross-operator
tx reads, including nullifiers, are now 403), attestation
request/get/evaluate/decision (previously missing — verdicts and
decision nullifiers were cross-operator readable), and enforce
(pre-existing bond check retained, attestation check added).
Ownership failures are 403; missing resources are 404. Public
verification endpoints remain public behind privacy-safe projections.

## Ownership rules

Every owner-scoped read/mutation resolves the resource's operator and
compares to the session operator. Unlinked transactions are denied to
operators (system-internal). No route performs ad-hoc comparisons.

## Public vs private endpoints

Public (no auth): `/health`, `/ready`, `/api/v1/public/*`,
`POST /api/v1/auth/session`. Everything else requires a principal.
Public serializers unchanged.

## Attestor isolation

Middleware (`requireAttestor`) + service check (defense in depth) +
identity-match guard. Secrets travel in a single header, are hashed
on arrival, never logged, never returned, never stored raw.

## Error model

401 missing/malformed/invalid/expired/revoked auth; 403
authenticated-but-unauthorized (ownership, ineligible attestor,
identity mismatch); existing sanitization preserved (no token hashes,
session IDs, secrets, or SQL in bodies).

## Frontend behavior

Central 401 hook clears the session, flags expiry, redirects to
`#/login`, which shows a one-time "session expired" notice.
`signOut()` best-effort revokes server-side first (hook-suppressed
to avoid loops), then clears locally. No new secrets in storage.
Wallet UI remains an explicit "unavailable" notice.

## Known limitations

No idle timeout (`last_used_at` deferred — needs migration + sweeper);
dev brute-force guard is per-process memory (multi-replica unsafe, but
production never reaches it); no rate limiting (Phase 9.5); sessions
table has no retention purge yet; wallet auth is Phase 11; system
principal is typed but not yet consumed by worker code.

## Tests

`apps/api/src/authz.test.ts` (10 tests: A–E, G) plus
`apps/web/src/test/client.test.tsx` additions (401 hook scoping,
expired notice). All existing suites untouched and green.
